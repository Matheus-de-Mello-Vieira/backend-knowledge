# Common Threats and Attacks

- **Definition:** Software attacks are malicious actions carried out by individuals or organizations aimed at compromising the security of computer systems or networks.
- **Targets:** These attacks can be directed at a variety of software components, including applications, operating systems, databases, and other technologies.

## Common Types of Software Attacks

### **Malware**  
  
- **Definition:** Malware, short for malicious software, is any software intentionally designed to damage, disrupt, gain unauthorized access to, or steal data from a computer system, network, or device.  
- **Examples:** Common forms of malware include [viruses](#Computer%20Viruses), [worms](#worms), [Trojans](#Trojans%20%28Trojan%20Horses%29), [ransomware](#ransomware), [spyware](#spyware), and [backdoors](#backdoors).

### Computer Viruses

- **Definition:** A malicious program designed to alter the way a computer operates, which spreads by attaching itself to a legitimate host file or executable program.
- **Execution Mechanism:** The defining characteristic of a virus is that it requires human interaction to execute. It remains dormant on a system until the user actively runs the infected program, opens a compromised document, or boots from an infected disk.
- **Impact:** Once activated, viruses can replicate and infect other files on the same local system. They are typically designed to cause local damage—corrupting or deleting data, formatting hard drives, or extracting sensitive information, often causing significant performance degradation.
- **Prevention:** The primary defense is utilizing robust, updated antivirus software. Users must also avoid downloading attachments from unknown sources, scan portable media (like USB drives) before use, and regularly back up critical data.
- **Recovery**: Recovery begins with immediate [Containment](../06%20Security%20Operations%20and%20Governance/Incident%20Response,%20Forensics,%20and%20Disaster%20Recovery.md#Containment) through isolation of the affected system to halt local replication.
    - The virus must be eradicated by removing malicious code and ensuring no traces remain before restoring files from clean, offline backups.
    - If critical files were deleted during the attack, "data carving" techniques may be used to recover fragments from unallocated disk space.
    - Finally, all systems must be patched and re-scanned to ensure the original vulnerability is closed before returning to normal operations.

### Worms

- **Definition:** A standalone malicious program that replicates itself to spread to other computers across a network.
- **Network Propagation:** Unlike a virus, a worm does not require a host file or human interaction to spread. It actively scans networks for security vulnerabilities in operating systems or applications and exploits those gaps to move automatically from machine to machine.
- **Impact:** Because they self-replicate and spread exponentially without user intervention, worms are notorious for consuming massive amounts of network bandwidth, leading to severe congestion or complete network failure. They also frequently carry malicious "payloads" designed to install backdoors or drop other malware (like ransomware) onto the newly infected machines.
- **Prevention:** Keeping operating systems and network software fully [patched and updated](../05%20Architecture%20and%20Infrastructure%20Security/Patch%20Management%20and%20Security%20Updates.md) is critical to closing the vulnerabilities that worms exploit. Network firewalls and Intrusion Prevention Systems (IPS) are also essential to block the unauthorized network traffic generated by worm propagation.
- **Recovery**: Because worms spread automatically through network gaps, recovery must prioritize [Containment](../06%20Security%20Operations%20and%20Governance/Incident%20Response,%20Forensics,%20and%20Disaster%20Recovery.md#Containment) through **network isolation** to "cut off" the compromised segment and immediately stop lateral movement to healthy systems.
    - Security teams should then use **diagnostic tools** to identify the specific vulnerability exploited and apply patches across all endpoints before they are reconnected.
    - Finally, a comprehensive scan of the environment is necessary to remove any "payloads" or backdoors left behind, while continuous monitoring of network traffic ensures that the "self-replication" cycle has been fully broken.

### Trojans (Trojan Horses)

- **Definition:** A type of malware that disguises itself as legitimate, safe, or desirable software to trick users into downloading and installing it.
- **Execution Mechanism:** Trojans rely entirely on social engineering rather than automated self-replication. A user might think they are downloading a free game, a helpful system utility, or an invoice from a colleague, but executing the file covertly unleashes the malware in the background.
- **Impact:** Trojans do not infect other files or self-replicate. Instead, their primary goal is usually to create a "backdoor" that gives a cybercriminal unauthorized, remote access to the system. Once inside, attackers can steal financial data, log keystrokes, install ransomware, or hijack the machine, turning it into a "zombie" node for DDoS botnets.
- **Prevention:** User education is paramount. Individuals must be trained to verify the source of their software, avoid pirated applications, and never execute unexpected email attachments. Endpoint Detection and Response (EDR) solutions are also crucial for identifying Trojan-like behavior (such as unauthorized outbound connections) after the software has been installed.
- **Recovery**: While the primary steps of [Containment](../06%20Security%20Operations%20and%20Governance/Incident%20Response,%20Forensics,%20and%20Disaster%20Recovery.md#Containment) through network isolation and data restoration follow the same logic as [**Computer Viruses**](#Computer%20Viruses), Trojan recovery must prioritize **Account Isolation** and a mandatory reset of all credentials.
    - Because Trojans are often used to steal login information or open "backdoors" for future access, simply cleaning the file is insufficient;
    - security teams must conduct [Live Forensics](Incident%20Response,%20Forensics,%20and%20Disaster%20Recovery.md#Types%20of%20digital%20forensics) to identify active remote connections and hunt for persistent payloads.
    - Restoration is only safe once the specific "entry point"—frequently a social engineering lure or a malicious attachment—has been identified and the vulnerability is closed to prevent the attacker from simply re-entering the system.

### Zero-Day Vulnerabilities

- **Definition:** A "zero-day" refers to a security vulnerability in a software or operating system that is entirely unknown to the developers and users.
- **Name Origin:** The term is used because developers have had "zero days" to fix the issue before cybercriminals begin exploiting it.
- **The Threat:** These vulnerabilities are highly dangerous as they allow attackers to take control of a system or network completely undetected. They are frequently used in highly targeted attacks or broader campaigns, such as malware and ransomware distribution.
- **Protection:** To mitigate zero-day threats, it is crucial to keep software and operating systems updated with the latest [security patches](../05%20Architecture%20and%20Infrastructure%20Security/Patch%20Management%20and%20Security%20Updates.md). Additional measures include using firewalls, intrusion detection systems, updated antivirus software, and practicing safe browsing habits (e.g., avoiding suspicious links, files, and unknown emails).
- **Recovery**: Recovery from a zero-day is uniquely difficult because a standard vendor patch is not immediately available. 
    - Similar to the process for [**Computer Viruses**](#Computer%20Viruses), initial efforts must focus on **[Containment](../06%20Security%20Operations%20and%20Governance/Incident%20Response,%20Forensics,%20and%20Disaster%20Recovery.md#Containment) and Isolation**—often by taking the affected service offline entirely—to prevent further damage.
    - Real-world recovery involves implementing temporary "workarounds" or configuration changes identified through [**Root Cause Analysis**](../06%20Security%20Operations%20and%20Governance/Incident%20Response,%20Forensics,%20and%20Disaster%20Recovery.md#Root%20Cause%20Analysis) to block the exploit's specific behavior.
    - Full restoration should only be completed once the organization can validate that the "gap" is closed—either through a newly released official patch or a permanent architectural change—to ensure the system does not immediately face a re-incidence of the same attack.

### Ransomware

- **Definition:** A specific type of malicious software that encrypts the data on an infected system and demands a ransom payment to restore access to the files.
- **Execution:** Once the files are encrypted and inaccessible, a message is displayed demanding payment, usually in a cryptocurrency like Bitcoin, which makes tracking the attacker difficult. It is a growing threat for businesses and government organizations.
- **Common Propagation Methods:**
    - [**Phishing Emails**](#phishing): Fake emails containing malicious links or attachments that infect the system when downloaded.
    - **Compromised Websites:** Legitimate websites infected with malware that automatically downloads to a user's computer upon visiting.
    - **Outdated Software:** Exploiting known vulnerabilities in unpatched software to install the malware.
- **Prevention:** Organizations should maintain updated software, perform regular data backups, use firewalls and updated antivirus solutions, and train users to recognize [phishing](#phishing) attempts.
- **Recovery**: Organizations must complete [Containment](../06%20Security%20Operations%20and%20Governance/Incident%20Response,%20Forensics,%20and%20Disaster%20Recovery.md#Containment) and restore data from clean, offsite backups only after the specific entry point (the "gap") has been identified and patched to ensure the same ransomware cannot immediately re-infect the system upon its return to the network.
    - It is critical to verify the integrity of these backups to confirm they were not also encrypted or tampered with by the malware during the initial infection.
    - In cases where critical systems cannot be reliably operated, a full "failover" to a secondary, uncompromised environment may be necessary to maintain business continuity.

### Spyware

- **Definition:** A type of malware designed to secretly monitor user or system activity and collect sensitive information without the victim's knowledge or consent.
- **Execution Mechanism:** Spyware is commonly installed through bundled software, malicious email attachments, drive-by downloads, or as a secondary payload dropped by other malware such as Trojans.
- **Impact:** Once installed, spyware can capture credentials, browsing history, keystrokes, screenshots, financial data, or other confidential information, enabling identity theft, fraud, surveillance, or follow-on compromise.
- **Prevention:** Users should install software only from trusted sources, keep systems patched, use updated anti-malware protection, and remain cautious with unsolicited links, downloads, and attachments.
- **Recovery**: Following the same logic as [**trojans**](#Trojans%20%28Trojan%20Horses%29), recovery must prioritize [Containment](../06%20Security%20Operations%20and%20Governance/Incident%20Response,%20Forensics,%20and%20Disaster%20Recovery.md#Containment) through **Account Isolation** and a total reset of all credentials, as the primary goal of spyware is the theft of access data. 
    - Because spyware's main activity is sending data to external servers, security teams should use [live forensic](Incident%20Response,%20Forensics,%20and%20Disaster%20Recovery.md#Types%20of%20digital%20forensics) to analyze volatile RAM data and identify active network connections before shutting down the device.
    - Restoration from clean backups is only effective after a [**Root Cause Analysis (RCA)**](../06%20Security%20Operations%20and%20Governance/Incident%20Response,%20Forensics,%20and%20Disaster%20Recovery.md#Root%20Cause%20Analysis) identifies the entry point—such as a phishing link—and the system is patched to prevent the attacker from immediately harvesting new credentials.

### Injection Attacks

- **Definition:** A broad class of attack that occurs when an attacker sends untrusted data to an interpreter as part of a command or query.
- **Execution Mechanism:** The application fails to properly validate or sanitize user input. The interpreter (such as a database engine or OS shell) is "tricked" into executing unintended commands or accessing data without proper authorization.
- **Common Variants:**
    - **SQL Injection (SQLi):** Attacker injects malicious SQL code into input fields to manipulate backend database queries.
    - **Command Injection:** Attacker injects operating system commands to be executed on the host server.
    - **NoSQL Injection:** Targeting non-relational databases by manipulating query syntax (e.g., JSON).
- **Impact:** Injection attacks primarily target **Confidentiality** (stealing data) and **Integrity** (modifying or deleting data). In severe cases, they can lead to a total system compromise or a [backdoors](#Backdoors) installation.
- **Prevention:** - **Parameterized Queries:** The primary defense is the use of Prepared Statements, which ensure the interpreter treats input strictly as data, never as executable code.
	- **Static Code Analysis (SAST):** Automated tools should be used during the development phase to scan the source code for "sinkholes"—specific lines of code where unvalidated user input reaches a sensitive interpreter.
	- **Input Validation:** Implementing "allow-lists" to ensure input matches expected patterns (e.g., numeric-only fields).
	- **Principle of Least Privilege:** Limiting the permissions of the database or application account so that even a successful injection cannot drop tables or access the OS.
- **Recovery:** Recovery must begin with immediate [Containment](../06%20Security%20Operations%20and%20Governance/Incident%20Response,%20Forensics,%20and%20Disaster%20Recovery.md#Containment) through **Isolation** of the affected application or database to prevent further data exfiltration.
    - Security teams must conduct a [**Root Cause Analysis (RCA)**](../06%20Security%20Operations%20and%20Governance/Incident%20Response,%20Forensics,%20and%20Disaster%20Recovery.md#Root%20Cause%20Analysis) to identify the specific vulnerable input field and apply code-level patches.
    - Following the logic of [spyware](#Spyware), a total reset of potentially compromised credentials is required if the attacker gained access to user tables.
    - Finally, the database must be audited for unauthorized changes and restored from a clean backup if data integrity was compromised.

### Cross-Site Request Forgery (CSRF)

- **Definition:** A web security vulnerability that tricks a victim's web browser into executing an unwanted, unauthorized action on a trusted application where the victim is currently authenticated.
- **Execution Mechanism:** CSRF relies entirely on the fact that web browsers automatically include session cookies with every request sent to a specific domain. The attacker does not need to steal credentials directly. Instead, they use social engineering to lure the victim to a malicious webpage or link. When the authenticated user visits this page, a hidden script forces their browser to send an unauthorized request (such as a state-changing POST request) to the target application, which trusts the request because the victim’s valid authentication cookies are attached.
- **Impact:** CSRF primarily targets **Integrity** and **Authenticity** by forcing a legitimate user to unintentionally act as a proxy for the attacker. Depending on the permissions of the authenticated victim, an attacker can modify data on the server such as changing account email addresses, transferring funds, resetting passwords, or, if an administrative account is compromised, establishing persistent [backdoors](#backdoors).
- **Prevention:** Standard firewalls and input validation cannot block CSRF because the requests look identical to legitimate user actions. Defenses must be structurally integrated into the application:
    - **[CSRF Token](Web%20Application%20Security.md#Anti-CSRF%20Tokens)**
    - **SameSite Cookie Attributes:** Setting the `SameSite` attribute on session cookies to `Strict` or `Lax` ensures that the browser will not automatically send cookies along with cross-site requests, neutralizing the baseline execution mechanism.
    - **Re-Authentication for Critical Actions:** Forcing the user to re-enter their password or solve a CAPTCHA before completing sensitive operations breaks the automated nature of the attack.
- **Recovery:** Following the credential-reset and session-invalidation logic found in [**Spyware**](#spyware) and [**Trojans**](#Trojans%20%28Trojan%20Horses%29), recovery from a CSRF exploit requires an aggressive response to stop ongoing unauthorized actions:
    - Initial efforts must focus on immediate [Containment](../06%20Security%20Operations%20and%20Governance/Incident%20Response,%20Forensics,%20and%20Disaster%20Recovery.md#Containment) through **Session Termination** to globally invalidate all active session IDs, cookies, and tokens associated with the affected user base, cutting off any ongoing automated malicious requests.
    - Security teams must enforce **Account Isolation** and a mandatory multi-factor re-authentication via secure [Cryptographic Authentication](../02%20Identity%20and%20Access/01%20Authentication.md#Cryptographic%20Authentication) for all affected profiles.
    - A comprehensive **Root Cause Analysis (RCA)** must be conducted to identify the specific application endpoints that lacked proper token or `SameSite` protections, allowing code-level patches to be deployed before re-enabling access to the affected platform functions.

### Cross-Site Scripted Request

- **Definition:** A cross-site request that is automatically initiated and controlled by a malicious client-side script (such as JavaScript) running in a victim's browser, targeting a separate domain.
- **Execution Mechanism:** This is a script-driven variant of a network or application request. It typically occurs after an attacker successfully injects malicious code into a website. When an authenticated user triggers the script, it utilizes APIs like `fetch()` or `XMLHttpRequest` to automatically generate requests to external servers, leveraging the browser’s default behavior of attaching valid session cookies or authorization headers to cross-origin requests.
- **Impact:** It serves as a primary **Tool** or execution mechanism for higher-level attacks. It can target **Integrity** if used to execute unauthorized actions blindly ([Cross-Site Request Forgery](#Cross-Site%20Request%20Forgery%20(CSRF))), or it can target **Confidentiality** if used to query and extract sensitive data from an external application.
- **Prevention:** To defend against malicious scripted requests, organizations must enforce a strict **Content Security Policy (CSP)** to restrict which domains scripts can communicate with. Setting session cookies with `HttpOnly` blocks scripts from extracting session tokens directly, while configuring short-lived tokens and implementing **SameSite Cookie Attributes** ensures the browser withholds authentication credentials during cross-site script executions.
- **Recovery:** Following the session-invalidation and isolation logic found in [**Cross-Site Request Forgery (CSRF)**](#Cross-Site%20Request%20Forgery%20%28CSRF%29) and [**Trojans**](#Trojans%20%28Trojan%20Horses%29), recovery requires cutting off the script's ability to act on behalf of the user:
    - Initial efforts must focus on immediate **Session Termination** to globally invalidate active tokens, halting any automated requests currently being generated by the script.
    - Security teams must perform **Live Forensics** on the client-facing application to locate the injection point where the malicious script was planted.
    - A comprehensive **Root Cause Analysis (RCA)** must be conducted to patch the underlying application vulnerability (such as Cross-Site Scripting) that allowed the script injection, ensuring the attack vector is completely closed before forcing users to re-authenticate.

### Cross-Site Data Theft

- **Definition:** An application-layer compromise where an attacker successfully uses a cross-site mechanism to read and exfiltrate sensitive user data from a completely separate web origin.
- **Execution Mechanism:** Cross-Site Data Theft is fundamentally classified as an **Interception** attack operating at the application layer. While an attacker can easily force a browser to _send_ a cross-site request to a target application, the browser's **Same-Origin Policy (SOP)** naturally blocks the external site from reading the data returned in the response. To successfully commit data theft, the attacker must find misconfigurations in the target application's resource-sharing controls that inadvertently grant reading privileges to untrusted origins.
- **Impact:** This is a direct attack on **Confidentiality**. Unlike [CSRF](#Cross-Site%20Request%20Forgery%20%28CSRF%29), which focuses on blind execution, the ultimate **Goal** of Cross-Site Data Theft is to steal private records such as personal identifying information (PII), financial statements, or private messages and transmit them back to an attacker-controlled server.
- **Prevention:** The primary technical defense is the strict and accurate configuration of **Cross-Origin Resource Sharing (CORS)** headers. Applications must never use wildcard reflections (`Access-Control-Allow-Origin: *`) alongside credential sharing. Additionally, ensuring that sensitive data is only returned over `POST` requests requiring custom, unpredictable headers effectively prevents unauthorized cross-site reading.
- **Recovery:** Mirroring the response-handling and containment logic found in [**Spyware**](#spyware) and [**Injection Attacks**](#Injection%20Attacks), recovery must focus heavily on sealing the data leak:
    - Initial efforts must focus on immediate [Containment](../06%20Security%20Operations%20and%20Governance/Incident%20Response,%20Forensics,%20and%20Disaster%20Recovery.md#Containment) by modifying or temporarily disabling the vulnerable API endpoints to stop ongoing data exfiltration.
    - Security teams must run an automated configuration audit to identify where the **CORS** policy or access control rules were misconfigured.
    - A comprehensive **Root Cause Analysis (RCA)** is required to determine the exact volume and scope of the data intercepted during the breach. Access control lists (ACLs) and server headers must be strictly hardened to legitimate origins before returning the data services to production.
### Defacement

- **Definition:** An application- or infrastructure-layer attack where an actor maliciously alters the visual appearance, textual content, or structural components of an organization's public-facing digital asset (such as a website or web application).
- **Execution Mechanism:** Defacement is explicitly classified as a **Modification** attack operating at the application layer. It relies entirely on the attacker first exploiting underlying software vulnerabilities—such as **[Injection Attacks](#Injection%20Attacks)** or **[Port Scanning and Brute Force](#Port%20Scanning%20and%20Brute%20Force)**—or leveraging **[Phishing](#Phishing)** and **[Spyware](#Spyware)** to harvest valid administrative credentials. Once unauthorized access to the web server, Content Management System (CMS), or source code repository is achieved, the attacker replaces legitimate files with their own fabricated content.
- **Impact:** Defacement primarily targets **Integrity** and **Authenticity** by distorting official information and presenting an unauthorized interface to the public. While the physical availability of the underlying server may remain intact, the ultimate **Goal** is usually ideological sabotage, political activism, or reputational damage. It severely compromises consumer trust, signals that the organization's internal infrastructure is vulnerable, and can be used as a vector to host secondary malicious payloads or false announcements that fuel follow-on social engineering campaigns.
	- **Prevention:** Standard network-layer protections cannot block unauthorized application-level content changes. Defenses must be embedded into deployment workflows and access configurations:
	- **File Integrity Monitoring (FIM):** Utilizing specialized tools to continuously scan web directories against a known-good baseline, automatically alerting administrators or blocking unauthorized modifications to core system files.
	- **Principle of Least Privilege:** Restricting web server process permissions to "read-only" for source directories, ensuring that a compromised web application runtime cannot overwrite local files on the disk.
	- **Input Validation and Parameterized Queries:** Implementing rigorous code-level safeguards to eliminate injection vectors that grant unauthorized database or OS shell access.
	- **Multi-Factor Authentication (MFA):** Enforcing cryptographic or multi-factor authentication across all management consoles, hosting dashboards, and CMS backends to mitigate credential theft.
- **Recovery:** Mirroring the restoration and security patching logic found in **[Injection Attacks](#Injection%20Attacks)** and **[Computer Viruses](#Computer%20Viruses)**, recovery requires taking the altered asset offline, diagnosing the entry breach, and validating system integrity:
    - Initial efforts must focus on immediate [Containment](../06%20Security%20Operations%20and%20Governance/Incident%20Response,%20Forensics,%20and%20Disaster%20Recovery.md#Containment) through **service isolation**, either taking the vulnerable web application completely offline or routing traffic to a secure, static maintenance page to stop ongoing reputational damage and protect users from secondary scripts.
    - Security teams must enforce **Account Isolation** by terminating all active administrative sessions and forcing a mandatory reset of all portal and server credentials.
    - A comprehensive **[Root Cause Analysis (RCA)](../06%20Security%20Operations%20and%20Governance/Incident%20Response,%20Forensics,%20and%20Disaster%20Recovery.md#Root%20Cause%20Analysis)** is required to determine the exact security gap (e.g., an unpatched CMS vulnerability or a leaked password) that allowed entry, ensuring a code-level patch or configuration fix is applied.
    - Final restoration involves entirely wiping the compromised directories, restoring files from a trusted, offline backup, and performing a thorough [forensic investigation](Incident%20Response,%20Forensics,%20and%20Disaster%20Recovery.md#Digital%20Forensics) to confirm that no persistent **[backdoors](#backdoors)** or malicious configuration scripts were left behind before re-introducing the application to production traffic.
### Backdoors

- **Definition:** A hidden method or entry point that bypasses a system’s standard authentication or encryption measures, providing unauthorized access to a computer, network, or software application.
- **Execution Mechanism:** Backdoors are often established in two ways: they can be "hardcoded" by original developers for maintenance or troubleshooting (known as a trapdoor), or they can be installed maliciously by other malware, such as [**Trojans**](#Trojans%20%28Trojan%20Horses%29) or [**Worms**](#worms), to create a persistent, secret entrance for future use.
- **Impact:** The primary goal of a backdoor is **persistence**. It allows an attacker to regain access to a system at any time without the user's knowledge. Once inside, attackers can remotely execute commands, install additional malware, exfiltrate sensitive data, or monitor user activity indefinitely, often remaining undetected by standard security protocols.
- **Prevention:** Rigorous code audits and peer reviews are necessary to identify intentional or accidental backdoors in software. Organizations should also deploy **Endpoint Detection and Response (EDR)** and network monitoring tools to flag suspicious outbound connections or unauthorized administrative activity. Following the principle of least privilege ensures that even if a backdoor is accessed, the potential for damage is limited.
- **Recovery**: Similar to the isolation logic in [Computer Viruses], recovery must begin with [Containment](../06%20Security%20Operations%20and%20Governance/Incident%20Response,%20Forensics,%20and%20Disaster%20Recovery.md#Containment) by cutting off the attacker's remote access.
    - However, the unique challenge here is the search for "shadow" accounts or hidden scripts—standard restoration is insufficient if the backdoor remains in the backup.
    - Security teams must perform a thorough [forensic investigation](Incident%20Response,%20Forensics,%20and%20Disaster%20Recovery.md#Digital%20Forensics) to compare the current system against a known-good baseline.
    - **Account Isolation** and a mandatory reset of all administrative credentials are required to ensure that any "keys" stolen through the backdoor are rendered useless.

### Rootkits

- **Definition:** A highly sophisticated type of malware designed to hide its presence, as well as the presence of other malware such as [**spyware**](#spyware) or [**backdoors**](#backdoors), from the operating system and standard security tools.
- **Execution Mechanism:** The term comes from "root"—the most privileged account on Unix/Linux systems. Rootkits modify core operating system structures, APIs, or even kernel-level components. Instead of relying on social engineering to trick the user continuously, a rootkit establishes its deep-level presence by hooking directly into the OS's internal pathways, filtering out any information that would reveal its files, processes, or open network connections.
- **Impact:** Rootkits primarily target **Integrity** and long-term **Persistence**. Because they operate at the same or higher privilege level than the operating system itself, they can completely subvert local security controls. A rootkit can modify antivirus software so it skips scanning malicious files, make unauthorized configuration changes, or provide an attacker with permanent, invisible administrative access to the host server.
- **Prevention:** Since rootkits modify low-level system code, regular signature-based antivirus software often cannot detect them once installed. Prevention relies heavily on securing the boot process using technical controls like [Secure Boot](../05%20Architecture%20and%20Infrastructure%20Security/Linux%20Endpoint%20Security.md#Virus%20and%20Malware%20Protection) and the **Trusted Platform Module (TPM)** discussed in [Windows Security](Windows%20Security.md#BitLocker%20Drive%20Encryption%20Integration) to ensure that only cryptographically signed, untampered firmware and operating system components are loaded. Regular kernel-level file integrity monitoring (FIM) and deploying advanced **Endpoint Detection and Response (EDR)** tools capable of behavioral analysis are also critical.
- **Recovery:** Recovery from a rootkit is uniquely difficult because the operating system cannot be trusted to accurately report on its own status or cleanly delete the malware. Furthermore, because a rootkit operates with administrative or kernel-level privileges, you must always assume the infection has upgraded itself to a firmware-level **[bootkit](https://www.google.com/search?q=%23bootkits)**, so both have the same recoveries procedures.
	- A comprehensive **[**Root Cause Analysis (RCA)**](../06%20Security%20Operations%20and%20Governance/Incident%20Response,%20Forensics,%20and%20Disaster%20Recovery.md#Root%20Cause%20Analysis)** must be conducted to identify and patch the original entry point (such as a [Trojans](#Trojans%20(Trojan%20Horses)) or an unpatched vulnerability) that allowed the attacker to gain administrative privileges in the first place.

### Bootkits

- **Definition:** An extremely dangerous and advanced variant of a [**rootkit**](#rootkits) that infects the computer’s master boot record (MBR), volume boot record (VBR), or malicious Unified Extensible Firmware Interface (UEFI) / BIOS firmware.
- **Execution Mechanism:** While a standard rootkit targets the operating system kernel, a bootkit executes _before_ the operating system even begins to load. It hijacks the very early stages of the system startup sequence, allowing it to modify the OS kernel file in memory as it is being loaded from the disk, completely evading detection from any security controls operating inside the OS environment.
- **Impact:** Bootkits primarily target **Integrity** and achieve the highest possible level of **Persistence** on a compromised machine. Because they reside outside the standard file system, in the boot sector or firmware, they remain completely invisible to traditional antivirus software and Endpoint Detection and Response (EDR) agents. This gives the attacker permanent administrative control, allowing them to decrypt storage drives or inject other persistent payloads like [**spyware**](#spyware) or [**backdoors**](#backdoors) on every single boot.
- **Prevention:** Standard operating system protections are entirely bypassed by bootkits. Defenses must be hardware- and firmware-based, strictly utilizing [UEFI Secure Boot](../05%20Architecture%20and%20Infrastructure%20Security/Linux%20Endpoint%20Security.md#Virus%20and%20Malware%20Protection) to ensure that only cryptographically signed bootloaders can execute. Additional protections include enabling **Trusted Boot** and leveraging a **Trusted Platform Module (TPM)** for measured boot validation, as discussed in [Windows Security](../05%20Architecture%20and%20Infrastructure%20Security/Windows%20Security.md#BitLocker%20Drive%20Encryption%20Integration), keeping the motherboard's BIOS/UEFI firmware updated, and password-protecting the BIOS to prevent unauthorized boot-order changes.
- **Recovery:** Recovery from a bootkit is one of the most difficult challenges in incident response because the underlying hardware's boot process itself cannot be trusted.
    - Following the network isolation logic of [**Computer Viruses**](#Computer%20Viruses), the infected system must immediately undergo **[Containment](../06%20Security%20Operations%20and%20Governance/Incident%20Response,%20Forensics,%20and%20Disaster%20Recovery.md#Containment)** by being completely isolated from the network to stop lateral movement.
    - Simply formatting the operating system partition or replacing the hard drive is completely ineffective if the bootkit has infected the motherboard's UEFI/BIOS firmware. Security teams must perform an **offline firmware flash** using a verified, clean manufacturer binary from a secure, external write-protected device.
    - If the infection is limited to the boot sector of the storage drive, the system must be booted into a clean, trusted external environment (like a recovery live USB) to completely overwrite the Master Boot Record (using utilities like `bootrec /fixmbr`) or securely wipe the entire drive at a low level.
    - Once the firmware and boot sectors are validated as clean, full restoration can proceed by rebuilding the operating system from a verified baseline and restoring files from trusted, offline backups.
    - Finally, a comprehensive [**Root Cause Analysis (RCA)**](../06%20Security%20Operations%20and%20Governance/Incident%20Response,%20Forensics,%20and%20Disaster%20Recovery.md#Root%20Cause%20Analysis) is required to determine how the attacker obtained the kernel- or administrative-level privileges necessary to write to the boot sectors or flash the firmware in the first place, ensuring the initial vulnerability is permanently closed.

### Phishing

- **Definition:** A form of social engineering where attackers use deceptive communications to trick individuals into compromising their own security or sharing sensitive data.
- **Execution Mechanism:** Attackers typically send fake emails that contain malicious links or attachments. The attack relies on human error, as it requires the user to actively click a link or download a file to infect the system or reveal information.
- **Impact:** Phishing is a primary method for identity theft, allowing attackers to obtain private information such as names, addresses, Social Security Numbers, and financial details to conduct fraudulent transactions. It also serves as a common propagation method for malware, specifically ransomware.
- **Prevention:** The most critical defense is providing cybersecurity awareness training to teach users how to recognize phishing attempts. Additionally, individuals should remain vigilant, never share personal data on untrusted websites, and avoid executing unexpected email attachments.
- **Recovery**: If credentials were submitted, recovery follows the same protocol as [**trojans**](#Trojans%20%28Trojan%20Horses%29), prioritizing [Containment](../06%20Security%20Operations%20and%20Governance/Incident%20Response,%20Forensics,%20and%20Disaster%20Recovery.md#Containment) through **Account Isolation** and a global password reset for all affected services.
    - If a malicious attachment was opened, the response must shift to a [forensic investigation](Incident%20Response,%20Forensics,%20and%20Disaster%20Recovery.md#Digital%20Forensics) to identify any installed malware or [backdoors](#backdoors). Recovery is only complete once the organization validates that no unauthorized configuration changes—such as new "forwarding rules" in email accounts—were made during the period of unauthorized access.

### Human Error and Sabotage

- **Human Error:** Occurs when an employee accidentally compromises the organization's cybersecurity. Examples include falling for [phishing](#phishing) emails, clicking malicious links, using weak passwords, or inadvertently sharing confidential information.
- **Sabotage:** An intentional act to damage an organization's cybersecurity. This can be perpetrated by a disgruntled employee (e.g., stealing data, destroying systems, installing malware) or by external hackers motivated by financial or political gains.
- **Prevention (Human Error):** Provide cybersecurity awareness training, enforce strong password policies, restrict access to confidential data, and utilize robust security systems.
- **Prevention (Sabotage):** Implement strict access controls, monitor user activity, segregate duties, conduct background checks on potential hires, and limit sensitive data access to a strict need-to-know basis.

### Identity and Equipment Theft

- **Identity Theft:** Occurs when an attacker steals a person's private information (name, address, date of birth, SSN, financial details) to conduct fraudulent transactions, open bank accounts, or issue credit cards in the victim's name. Attackers obtain this data via [phishing](#phishing), stolen documents, or cyberattacks on databases.
- **Common Fraud Scenarios:** Purchasing cell phones or vehicles, financing electronics, and opening shell companies using stolen data.
- **Equipment Theft:** The physical loss or theft of electronic devices (laptops, smartphones, tablets), leading to unauthorized access to personal, financial, or corporate data.
- **Prevention:**
    - *For Equipment:* Install remote tracking/wiping software, use strong device passwords, and keep security software updated.
    - *For Identity:* Be vigilant against [phishing](#phishing), never share personal data on untrusted sites, monitor financial accounts regularly, and report suspicious activities immediately.

### Hardware and Power Failures

- **Hardware Failures:** The breakdown of physical computer components due to natural wear and tear, malfunctions, physical damage, or even cyberattacks (like DDoS) that overwork the hardware. This leads to service interruptions and potential data loss.
- **Power Failures:** Disruptions in the electrical supply caused by grid outages, lightning strikes, or faulty power equipment, which can instantly interrupt services and cause data loss.
- **Prevention:**
    - *Hardware:* Implement regular monitoring, diagnostic testing, data backups, firmware updates, and strong encryption/passwords.
    - *Power:* Install backup power systems (such as generators or Uninterruptible Power Supplies - UPS), perform regular electrical maintenance, and utilize surge protectors to defend against power spikes.
### **Insider Threats**

- **Definition:** Security threats that originate from within the organization, such as employees, former employees, contractors, or business associates who have authorized access to the network, system, or data.
- **Execution Mechanism:** Unlike external attackers who must bypass the perimeter, insider threats leverage their legitimate access to bypass standard security controls. This can manifest as **Human Error** (accidental) or **Sabotage** (intentional).
- **Common Variants:**
    - **The Malicious Insider:** An individual who intentionally steals data (Identity/Equipment Theft) or destroys systems for financial gain, revenge, or political motives.
    - **The Negligent Insider:** An individual who unintentionally creates a vulnerability, such as falling for [Phishing](#Phishing) or misconfiguring a database.
    - **The Compromised Insider:** A legitimate user whose credentials have been stolen via [Spyware](#Spyware) or [Trojans](#Trojans%20%28Trojan%20Horses%29), allowing an external actor to act as an insider.
- **Impact:** These threats primarily target **Confidentiality** through data exfiltration and **Availability** through the destruction of hardware or power systems. Because the actor is trusted, they can often operate undetected for long periods.
- **Prevention:**
    - **Principle of Least Privilege:** Limit sensitive data access to a strict need-to-know basis to ensure that even if an account is compromised, the damage is contained.
    - **Segregation of Duties:** Ensure that no single individual has enough authority to execute a high-risk transaction or sabotage a system end-to-end.
    - **User Behavior Analytics (UBA):** Utilize monitoring tools to flag suspicious administrative activity or unusual outbound data transfers.
    - **Cybersecurity Awareness Training:** Educate staff to reduce **Human Error** and recognize the signs of social engineering.
- **Recovery:**
    - [**Containment**](../06%20Security%20Operations%20and%20Governance/Incident%20Response,%20Forensics,%20and%20Disaster%20Recovery.md#Containment) through **Account Isolation**: Immediately revoke all access for the suspected individual and perform a mandatory reset of administrative credentials.
    - **Forensic Investigation:** Conduct [live forensic](Incident%20Response,%20Forensics,%20and%20Disaster%20Recovery.md#Types%20of%20digital%20forensics) to determine the full scope of the data accessed or modified.
    - [**Root Cause Analysis (RCA)**](../06%20Security%20Operations%20and%20Governance/Incident%20Response,%20Forensics,%20and%20Disaster%20Recovery.md#Root%20Cause%20Analysis): Identify whether the breach was due to a process failure (Human Error) or a gap in technical controls (Sabotage).
    - **System Restoration:** Restore any deleted or corrupted data from clean, offsite backups and update access control lists (ACLs) to prevent a re-incidence.
## Network Threats

We can classify the various types of network attacks and/or threats by the attacker's level of interaction with the data:
- **Active Attacks:** These are attacks that act upon the information being transmitted over the network. They involve interrupting, modifying, or fabricating data.
- **Passive Attacks:** These are attacks that intercept the data traveling across the network but do not act upon or alter it in any way. They merely make a copy of the information (e.g., eavesdropping or wiretapping).

We can also classify them by their impact on the physical flow of information between the source and destination:
- **Interruption:** The information leaves the source but cannot reach the destination because it has been blocked or destroyed in some way. This is an attack on *Availability* (e.g., a Denial of Service attack).
- **Interception :** The information leaves the source, but an attacker manages to intercept and copy it before it reaches the destination. This is an attack on *Confidentiality* (e.g., packet sniffing or wiretapping).
- **Modification:** The information leaves the source and is intercepted by the attacker, who alters the data before forwarding it to the destination. This is an attack on *Integrity* (e.g., a Man-in-the-Middle attack altering a message).
- **Fabrication:** The information is entirely manufactured by the attacker, who falsifies (spoofs) the source address of the information to deceive the destination into believing it came from a legitimate user. This is an attack on *Authenticity* (e.g., IP spoofing or injecting fake routing data).

### Types

#### Packet Sniffing

- **Definition:** A passive network attack where software or hardware tools are used to monitor, intercept, and log data packets flowing across a network interface.
- **Execution Mechanism:** This technique is explicitly classified as an **Interception** attack operating at the network layer. The attacker deploys packet analyzers or packet sniffing programs—such as [Wireshark](06%20Network%20Monitoring.md#Wireshark)—to capture copies of network traffic as it travels from the source to the destination. This is a **Passive Attack** because the sniffer merely reads or duplicates the data passing through the network without altering, interrupting, or manipulating the packets in transit.
- **Impact:** Packet sniffing is a direct attack on **Confidentiality**. If network traffic is transmitted in clear text (unencrypted), the attacker can easily extract highly sensitive information, such as plain-text authentication credentials, session identifiers, financial data, or proprietary business communications. Captured tokens or credentials can subsequently be used to fuel higher-level active exploits, such as a **[Replay Attack](#Replay%20Attack%20%28Session%20Replay%20/%20Token%20Replay%29)** or unauthorized **[Identity Theft](#Identity%20and%20Equipment%20Theft)**.
- **Prevention:** The absolute primary defense against packet sniffing is the universal enforcement of strong, end-to-end cryptographic protocols—such as **[TLS](06%20TLS.md)**, **HTTPS**, and **SSH**—to ensure that even if network packets are intercepted, they remain entirely unreadable to unauthorized eyes. Networks should also be structurally segmented using managed switches rather than hubs, and protected via [Intrusion Detection System (IDS)](Intrusion%20Detection%20and%20Prevention.md#Intrusion%20Detection%20System%20(IDS)) configured to flag network interfaces running in promiscuous mode (which is required to sniff broader network traffic).
- **Recovery:** Mirroring the credential-invalidation and session-termination logic applied to other data-exposure vectors like **[Man-in-the-Middle (MitM)](#Man-in-the-Middle%20%28MitM%29)** or **[Spyware](#Spyware)**, recovery must assume that any unencrypted data traversing the affected network segment has been fully compromised:
    - Initial efforts must focus on immediate [Containment](../06%20Security%20Operations%20and%20Governance/Incident%20Response,%20Forensics,%20and%20Disaster%20Recovery.md#Containment) through **Session Termination** to globally invalidate active tokens, combined with a mandatory password reset for all user or system accounts whose credentials may have been transmitted in clear text.
    - Security teams must run a comprehensive **Root Cause Analysis (RCA)** to locate the physical or logical placement of the rogue sniffer (e.g., a compromised local endpoint, an unauthorized network device, or a misconfigured switch port mirror) and isolate that node from the network.
    - Restoration is only complete once network engineering teams audit traffic baselines and permanently decommission or upgrade any remaining legacy applications or protocols that continue to broadcast unencrypted data across the production environment.

#### Whois Queries

- **Definition:** A passive reconnaissance technique where attackers query public registry databases to gather administrative, technical, and ownership information associated with a target's domain name or IP address block.
- **Execution Mechanism:** This technique operates strictly within the **Interception** (reconnaissance) phase of an attack lifecycle. It is classified as a **Passive Attack** because the attacker does not interact directly with the target’s network infrastructure or systems. Instead, the attacker queries external, publicly accessible Whois directories to systematically map out corporate details, contact records, and registrar data associated with the domain.
- **Impact:** Whois queries primarily target information **Confidentiality** by turning publicly available metadata into actionable intelligence. While querying a public directory does not break technical security controls, the obtained data—such as administrative names, corporate physical addresses, phone numbers, and email structures—is actively used to build highly targeted social engineering and **[Phishing](#Phishing)** campaigns. It provides the contextual baseline needed to trick employees into believing an external communication is legitimate.
- **Prevention:** The primary technical defense against Whois reconnaissance is enforcing **Whois Privacy Protection** (often called domain privacy or redaction services) through the domain registrar to mask corporate names, personal phone numbers, and direct email addresses with anonymous proxy data. Organizations should also use generic, role-based aliases (e.g., `hostmaster@company.com`) rather than personal employee identities for mandatory public registry fields, and continuously train personnel to recognize corporate impersonation tactics.
- **Recovery:** Because a Whois query is a passive lookup on a third-party server, it does not leave footprints on the target organization's local systems, making standard isolation or software containment irrelevant. Recovery is focused entirely on mitigating the operational risk of the exposed data:
    - Initial efforts must focus on immediate risk mitigation by auditing and activating privacy redaction services across all corporate domain portfolios to "cut off" the source of open-source intelligence harvesting.
    - Security operations teams must conduct a proactive review of the specific data points that were publicly accessible (such as a specific administrator's name) and alert internal security monitors or email filters to watch for incoming spear-phishing lures targeting those specific individuals or departments.
    - Finally, a specialized **Root Cause Analysis (RCA)** should be conducted to establish a standardized corporate policy ensuring that any newly registered domain or network asset automatically defaults to a strict privacy posture before being exposed to the public internet.
#### IP Spoofing

- **Definition:** A technique where an attacker creates Internet Protocol (IP) packets with a falsified source IP address to impersonate another computer system or user.
- **Execution Mechanism:** IP spoofing is classified as a **Fabrication** attack. The attacker entirely manufactures the information and falsifies the source address to deceive the destination into believing the communication originated from a legitimate or trusted source.
- **Impact:** This is primarily an attack on **Authenticity**. It is frequently used to bypass IP-based authentication filters or to conduct **DDoS attacks**, where a botnet floods a target with traffic that appears to come from a vast array of legitimate IP addresses, making the attack harder to block.
- **Prevention:** To defend against spoofing, organizations should utilize **firewalls** and **Intrusion Prevention Systems (IPS)** to monitor for anomalous traffic patterns. Implementing ingress and egress filtering on routers—which verifies that incoming and outgoing packets have legitimate source addresses—is also a critical technical control.
- While the network isolation logic discussed in [**Computer Viruses**](#Computer%20Viruses) is a necessary first step if a breach occurs, IP Spoofing recovery specifically requires [Containment](../06%20Security%20Operations%20and%20Governance/Incident%20Response,%20Forensics,%20and%20Disaster%20Recovery.md#Containment) before a transition to [Cryptographic Authentication](01%20Authentication.md#Cryptographic%20Authentication).
    - Because the "trust" in the IP address has been compromised, security teams must implement certificates or tokens that do not rely on the source IP.
    - A thorough [**Root Cause Analysis (RCA)**](../06%20Security%20Operations%20and%20Governance/Incident%20Response,%20Forensics,%20and%20Disaster%20Recovery.md#Root%20Cause%20Analysis) is then used to update firewall rules and access control lists (ACLs) to block the specific ranges or patterns exploited during the attack, ensuring that the same spoofing technique cannot be used to re-enter the network.

#### ARP Spoofing

- **Definition:** A network attack where an attacker sends falsified Address Resolution Protocol (ARP) messages over a local area network to link their MAC address with the legitimate IP address of an authorized network resource, such as the default gateway.
- **Execution Mechanism:** This technique is classified as a **Modification** attack that directly enables **Interception**. The attacker floods the local network segment with fraudulent ARP responses, manipulating and "poisoning" the ARP caching tables of the victim's machine and the local router. By abusing the stateless nature of the ARP protocol, the attacker tricks both devices into mapping the target IP addresses to the attacker's physical hardware address (MAC address). This imperceptibly inserts the attacker directly into the local data path.
- **Impact:** ARP Spoofing serves as a foundational execution mechanism for a local **[Man-in-the-Middle (MitM)](#Man-in-the-Middle%20%28MitM%29)** exploit. It severely compromises both **Confidentiality** and **Integrity**. Once positioned between the victim and the router, all inbound and outbound network traffic flows through the attacker's machine. This allows them to seamlessly execute **[Packet Sniffing](#Packet%20Sniffing)** to view sensitive data in clear text, alter data packets on the fly, or drop packets entirely to cause a localized **[Denial of Service (DoS)](#DoS%20%28Denial%20of%20Service%29)** condition.
- **Prevention:** The primary technical control against ARP table manipulation is the implementation of **Dynamic ARP Inspection (DAI)** on enterprise network switches, which validates ARP packets against a trusted database of IP-to-MAC mappings (DHCP snooping binding table). Organizations should also enforce **MAC Limiting** and Port Security on switches to restrict unauthorized network configurations, or utilize static ARP tables for critical infrastructure links to block automated overwrites.
- **Recovery:** Mirroring the routing-flush and containment logic found in **[DNS Poisoning](#DNS%20Poisoning%20%28DNS%20Cache%20Poisoning%29)** and **[Man-in-the-Middle (MitM)](#Man-in-the-Middle%20%28MitM%29)**, recovery requires immediate clearing of the compromised local network tables:
    - Initial efforts must focus on immediate [Containment](../06%20Security%20Operations%20and%20Governance/Incident%20Response,%20Forensics,%20and%20Disaster%20Recovery.md#Containment) by isolating the attacker's physical node from the switch fabric and forcing a manual flush of the poisoned ARP caches across all affected client machines and the local router interfaces to restore legitimate paths.
    - Because data was actively intercepted, security teams must deploy **Session Termination** to globally invalidate active session tokens and initiate a mandatory credential reset for any user profiles active during the period of interception.
    - A comprehensive **Root Cause Analysis (RCA)** must be completed to investigate the initial host compromise that allowed the attacker to gain local network access, ensuring switch port configurations are hardened with DAI before re-introducing the segment to production.
#### Man-in-the-Middle (MitM)

- **Definition:** A type of network attack where an attacker intercepts and potentially alters the communication between two parties who believe they are communicating directly with each other.
- **Execution Mechanism:** This is classified as a **Modification** attack. The information leaves the source and is intercepted by the attacker, who then alters the data before forwarding it to the destination. It can also involve **Interception**, where the attacker makes a copy of the data traveling across the network.
- **Impact:** It is a primary attack on **Integrity**, as the information is changed during transmission. Because the data is also intercepted, it compromises **Confidentiality**. This allows attackers to eavesdrop on private conversations, steal credentials, or manipulate the contents of a message (e.g., changing the destination of a bank transfer).
- **Prevention:** Defenses include utilizing **Intrusion Prevention Systems (IPS)** and **firewalls** to detect and block unauthorized network activity. Strong encryption is also vital to ensure that even if data is intercepted, it remains unreadable and its integrity can be verified.
- **Recovery**: Following the credential-reset logic found in [**Spyware**](#spyware) and [**Trojans**](#Trojans%20%28Trojan%20Horses%29), recovery must prioritize **Session Termination** for all active accounts to invalidate any stolen session cookies.
    - Security teams should perform a [forensic investigation](Incident%20Response,%20Forensics,%20and%20Disaster%20Recovery.md#Digital%20Forensics) to pinpoint the interception point—whether it was a local network vulnerability or a broader DNS compromise.
    - Restoration is only complete once the organization enforces strict [Cryptographic Authentication](01%20Authentication.md#Cryptographic%20Authentication) and validates that no unauthorized data modifications occurred during the breach period.

#### DoS (Denial of Service)

- **Definition:** A cyberattack intended to make a computer, network, or online service unavailable to its intended users by disrupting services of a host connected to the Internet.
- **Execution Mechanism:** Unlike its distributed counterpart, a standard DoS attack typically originates from a **single source** or one specific internet connection. The attacker sends a constant stream of service requests or exploits a software vulnerability to crash the system or exhaust its resources (such as CPU or memory).
- **Impact:** This is primarily an attack on **Availability**, categorized as an **Interruption**. It prevents legitimate traffic from reaching its destination, leading to service downtime and potential loss of productivity or revenue.
- **Prevention:** Defenses include utilizing **firewalls** and **Intrusion Prevention Systems (IPS)** to identify and block the attacking IP address. **Rate-limiting** traffic requests is also an effective way to prevent a single source from overwhelming the system.
- Following the network isolation logic discussed in [**Computer Viruses**](#Computer%20Viruses), DoS recovery begins with [Containment](../06%20Security%20Operations%20and%20Governance/Incident%20Response,%20Forensics,%20and%20Disaster%20Recovery.md#Containment) by identifying and blocking the attack source (using techniques like ACLs or blackholing).
    - Restoration focuses on clearing processing queues and re-enabling systems that were forced offline or "hung" by the surge.
    - Recovery is only complete after a [**Root Cause Analysis (RCA)**](../06%20Security%20Operations%20and%20Governance/Incident%20Response,%20Forensics,%20and%20Disaster%20Recovery.md#Root%20Cause%20Analysis) is used to update filtering rules and adjust resource scaling policies to better handle similar traffic spikes in the future.
#### Teardrop Attack

- **Definition:** A specific type of network hardware and protocol exploit where an attacker sends fragmented, malformed Internet Protocol (IP) packets with overlapping offsets to a target machine.
- **Execution Mechanism:** Teardrop is classified as an **Interruption** attack operating at the network layer. The attack exploits vulnerabilities in the way operating systems reassemble fragmented IP packets. Normally, when data packets are too large to pass through a network segment, routers break them into smaller fragments, and the destination OS uses the "Fragment Offset" field in the IP header to piece them back together in the correct order. In a Teardrop attack, the offender fabricates packets with intentionally overlapping and invalid offset values. When the target operating system attempts to reassemble these conflicting fragments, the TCP/IP stack encounters a memory management error, causing the system to crash, freeze, or reboot.
- **Impact:** This is primarily an attack on **Availability**, categorized as a network-driven **Interruption**. Driven by sabotage or service disruption, a Teardrop attack acts as a highly effective mechanism for a localized **[Denial of Service (DoS)](#DoS%20%28Denial%20of%20Service%29)**. Because it targets a fundamental vulnerability in the operating system's network stack rather than simply flooding the network pipe with raw volume, it can completely disable a target host or server using relatively low bandwidth.
- **Prevention:** Standard rate-limiting cannot block Teardrop exploits because the attack does not rely on massive traffic volume. Defenses must rely on protocol validation and operating system hardening:
    - **Network Firewalls and IPS:** Utilizing hardware firewalls or [Intrusion Prevention System (IPS)](Intrusion%20Detection%20and%20Prevention.md#Intrusion%20Prevention%20System%20(IPS)) configured to inspect packet fragments, drop packets with overlapping offsets, or reassemble fragments safely before passing them to the internal network.
    - **OS Patch Management:** Keeping host operating systems and network driver firmware fully updated, as modern OS network stacks have been patched to recognize and safely discard malformed fragment offsets.
    - **Disabling Fraggle-susceptible Features:** Restricting the acceptance of fragmented packets at the perimeter router or edge firewall if fragmentation is not required for business operations.
- **Recovery:** Following the network containment, system clearing, and patching logic found in **[DoS (Denial of Service)](#DoS%20%28Denial%20of%20Service%29)** and **[Worms](#Worms)**, recovery requires isolating the target, clearing the hung state, and applying code-level fixes:
    - Initial efforts must focus on immediate [Containment](../06%20Security%20Operations%20and%20Governance/Incident%20Response,%20Forensics,%20and%20Disaster%20Recovery.md#Containment) through **network isolation**, temporarily cutting off the affected network interface or updating upstream firewall Access Control Lists (ACLs) to drop incoming fragmented packets from the attacking source.
    - Because the attack causes kernel-level failure, restoration requires a physical or remote power cycle to clear corrupted memory processing queues and re-enable systems that were forced offline or "hung" by the malformed packets.
    - A comprehensive **[Root Cause Analysis (RCA)](../06%20Security%20Operations%20and%20Governance/Incident%20Response,%20Forensics,%20and%20Disaster%20Recovery.md#Root%20Cause%20Analysis)** must be completed to identify why the host's operating system failed to discard the overlapping fragments, leading directly to the deployment of vendor security patches or OS updates to close the underlying network stack vulnerability permanently before returning the machine to production.
#### Malformed Packet Attack

- **Definition:** A type of network infrastructure exploit where an attacker intentionally crafts and transmits network packets that violate established protocol specifications (RFCs) or contain invalid, corrupted, or contradictory header fields.
- **Execution Mechanism:** This technique is classified as an **Interruption** attack operating at the network or transport layers. It exploits poor input validation or parsing logic flaws within a target operating system’s or network device's TCP/IP stack. Unlike volumetric attacks that flood bandwidth, a malformed packet attack relies on structural anomalies (e.g., invalid TCP flag combinations, mismatched header lengths, or illegal options). When the target system attempts to parse these non-compliant attributes, it triggers a memory management exception, buffer overflow, or kernel panic.
- **Impact:** This is a direct attack on **Availability**, acting as a network-driven **[Denial of Service (DoS)](#DoS%20%28Denial%20of%20Service%29)**. Driven by sabotage or infrastructure disruption, a malformed packet attack can instantly crash, freeze, or force a reboot of critical perimeter defenses, such as firewalls and routers, or core host servers. Because it relies on systemic software flaws rather than raw traffic volume, a single strategically sent malformed packet can completely take down an unpatched asset.
- **Prevention:** Defenses must be structurally integrated into perimeter devices and systems via protocol compliance checking:
    - **Deep Packet Inspection (DPI):** Configuring perimeters, firewalls, and [Intrusion Prevention Systems (IPS)](Intrusion%20Detection%20and%20Prevention.md#Intrusion%20Prevention%20System%20(IPS)) to strictly enforce protocol compliance, automatically dropping any incoming packets that do not adhere to standard RFC structures before they reach internal hosts.
    - **OS and Firmware Patch Management:** Ensuring that host operating systems, router firmware, and security appliances are continuously updated. This patches known memory leak or crash vulnerabilities within the low-level network parsing libraries.
    - **Strict Ingress Filtering:** Implementing packet-sanity checks at the edge router to filter out bizarre, logically impossible flag states (such as "Xmas packets" where FIN, URG, and PSH flags are set simultaneously).
- **Recovery:** Mirroring the system-clearing and patching logic found in **[Teardrop Attack](#Teardrop%20Attack)** and **[DoS (Denial of Service)](#DoS%20%28Denial%20of%20Service%29)**, recovery requires isolating the target, restoring the device state, and sealing the parsing vulnerability:
    - Initial efforts must focus on immediate [Containment](../06%20Security%20Operations%20and%20Governance/Incident%20Response,%20Forensics,%20and%20Disaster%20Recovery.md#Containment) through **network isolation** or updating upstream boundary rules to filter out the specific anomalous packet structure, stopping ongoing disruption.
    - Because the attack results in a kernel-level failure or a locked system state, restoration requires a physical or remote power cycle (reboot) to clear the corrupted buffer processing queues and restore standard availability.
    - A comprehensive **[Root Cause Analysis (RCA)](../06%20Security%20Operations%20and%20Governance/Incident%20Response,%20Forensics,%20and%20Disaster%20Recovery.md#Root%20Cause%20Analysis)** must be executed using packet captures from the edge monitors to determine the precise field abnormality that triggered the crash, allowing security engineering teams to deploy a targeted vendor patch or strict firewall filter to close the exploit vector entirely.
#### DDoS (Distributed Denial of Service)

- **Definition:** A sophisticated cyberattack aimed at overwhelming an online system or service with excessive network traffic from multiple sources, rendering it unavailable to legitimate users.
- **Execution Mechanism:** These attacks are carried out using a **"botnet"**—a massive network of infected computers and devices (often called "zombies") worldwide controlled remotely by an attacker. The attacker commands the botnet to flood the target server with fake traffic requests or excessive network packets simultaneously.
- **Impact:** Like the standard DoS, this is an attack on **Availability** through **Interruption**. Driven by sabotage, extortion, or espionage, DDoS attacks can severely impact critical infrastructure (banking, healthcare, government) and cause significant financial losses. Because the attack traffic originates from thousands of different sources, it is much harder to filter or block than a single-source DoS attack.
- **Prevention:** Effective protection requires utilizing **load balancers** to distribute traffic, **firewalls**, and **IPS**. Many organizations also partner with specialized cybersecurity service providers for real-time monitoring and advanced traffic scrubbing to mitigate massive floods of data.
- **Recovery:** The recovery process follows the same fundamental logic as a [DoS] attack, but at a significantly larger scale.
    - Because the attack originates from a "botnet" of thousands of sources, recovery must prioritize [Containment](../06%20Security%20Operations%20and%20Governance/Incident%20Response,%20Forensics,%20and%20Disaster%20Recovery.md#Containment) through **automated traffic filtering** and the use of global scrubbing centers to isolate malicious traffic from legitimate user requests.
    - Once the immediate flood is contained, teams must perform a [**Root Cause Analysis (RCA)**](../06%20Security%20Operations%20and%20Governance/Incident%20Response,%20Forensics,%20and%20Disaster%20Recovery.md#Root%20Cause%20Analysis) to identify if the DDoS was a "smoke screen" for a deeper breach, such as the installation of a [**backdoor**](#backdoors) or [**spyware**](#spyware). Final restoration involves gradually re-introducing traffic while monitoring for a re-incidence of the attack.

#### Replay Attack (Session Replay / Token Replay)

- **Definition:** A cyberattack where a valid data transmission—specifically credential data, session tokens, or authentication cookies—is maliciously or fraudulently intercepted and repeated or delayed to gain unauthorized access to a website, system, or network.
- **Execution Mechanism:** This is primarily classified as an **Interception** attack followed by a **Fabrication** or **Replay** phase. The attacker captures sensitive authentication tokens as they cross the network or steals them directly from storage (such as browser cookies). Without needing to decrypt or know the actual password, the attacker simply re-transmits the valid token to the destination system, deceiving it into treating the malicious session as a legitimate, pre-authenticated user session.
- **Impact:** This is a direct attack on **Authenticity** and **Confidentiality**. Because the stolen token represents an already verified identity, the attacker completely bypasses the login screen, hijacking the user's active session. This allows them to perform unauthorized actions, access private user data, or escalate privileges within the target system while appearing as a trusted user.
- **Prevention:** To defend against replay attacks, organizations must implement **one-time tokens (nonces)**, short-lived session expirations, and time-stamping mechanisms to ensure a packet or token cannot be reused past its strict validity window. Utilizing **Transport Layer Security (TLS)** prevents the baseline interception of data over the network, while marking cookies as `HttpOnly` and `Secure` protects tokens from local script-based extraction.
- **Recovery:** Mirroring the credential-reset logic found in **[Spyware](#Spyware)** and **[Trojans](#Trojans%20%28Trojan%20Horses%29)**, recovery from a replay attack must immediately prioritize **Session Termination** to globally invalidate all active session IDs, cookies, and bearer tokens associated with the compromised accounts.
    - Security teams must deploy immediate [Containment](../06%20Security%20Operations%20and%20Governance/Incident%20Response,%20Forensics,%20and%20Disaster%20Recovery.md#Containment) steps, forcing all affected identities to undergo multi-factor re-authentication via secure [Cryptographic Authentication](../02%20Identity%20and%20Access/01%20Authentication.md#Cryptographic%20Authentication).
    - A comprehensive **[Root Cause Analysis (RCA)](../06%20Security%20Operations%20and%20Governance/Incident%20Response,%20Forensics,%20and%20Disaster%20Recovery.md#Root%20Cause%20Analysis)** is required to determine how the cookie or token was harvested (e.g., via network eavesdropping or a local **[Man-in-the-Middle (MitM)](#Man-in-the-Middle%20%28MitM%29)** exploit) so that token lifetime policies can be tightened and binding mechanisms (like binding tokens to the specific client TLS session) can be applied.

#### DNS Poisoning (DNS Cache Poisoning)

- **Definition:** A type of cyberattack where an attacker introduces fraudulent data into the cache of a Domain Name System (DNS) resolver, causing the server to return an incorrect IP address for a given domain name.
- **Execution Mechanism:** DNS Poisoning is classified as a **Modification** attack. The attacker exploits vulnerabilities in the DNS protocol—such as guessing transaction IDs—to intercept or outrun legitimate query resolutions, injecting a fake resource record into the resolver's local cache. As a result, subsequent client requests are diverted away from the real destination.
- **Impact:** This is a severe attack on **Integrity** and **Availability**, often resulting in a localized **Denial of Service (DoS)** or serving as a stepping stone for **Man-in-the-Middle (MitM)** credential harvesting. Because the name resolution table is altered, legitimate traffic is blocked from accessing the intended servers (causing a DoS condition for that user base). Alternatively, users may be transparently routed to malicious replica sites designed to steal data.
- **Prevention:** To defend against cache poisoning, organizations must implement **DNSSEC (Domain Name System Security Extensions)**, which adds cryptographic signatures to DNS records to verify their authenticity. Additionally, configured DNS resolvers should use source port randomization and strong cryptographically secure random transaction IDs to make response spoofing mathematically impractical.
- **Recovery:** Similar to the network containment and queue-clearing logic discussed in **[DoS](#DoS%20%28Denial%20of%20Service%29)**, recovery from DNS poisoning requires immediate local [Containment](../06%20Security%20Operations%20and%20Governance/Incident%20Response,%20Forensics,%20and%20Disaster%20Recovery.md#Containment) to purge the compromised routing data.
    - Security teams must manually flush the corrupted DNS cache files on affected resolvers and client machines to remove the fake entries.
    - Once the cache is cleared, teams must execute a [forensic investigation](../06%20Security%20Operations%20and%20Governance/Incident%20Response,%20Forensics,%20and%20Disaster%20Recovery.md#Digital%20Forensics) to ensure no underlying configurations were permanently altered, followed by a **[Root Cause Analysis (RCA)](../06%20Security%20Operations%20and%20Governance/Incident%20Response,%20Forensics,%20and%20Disaster%20Recovery.md#Root%20Cause%20Analysis)** to evaluate why the resolver accepted unauthenticated responses, enforcing strict validation checks before re-introducing the server to production traffic.

#### Port Scanning and Brute Force

- **Definition:** A multi-phase reconnaissance and access attack where individuals use automated tools to discover entry points across network protocols and attempt to crack system authentication mechanisms.
- **Execution Mechanism:** This technique operates as a combination of an **Interception** (reconnaissance) phase and a **Fabrication** or unauthorized access phase. Attackers deploy software like Nmap to systematically scan network interfaces for open TCP and UDP ports to identify active services. Concurrently, tools like Hydra and John the Ripper are used to launch dictionary or brute-force attacks against discovered authentication prompts—frequently targeting default passwords or cracking weak encryption keys on legacy wireless networks protected by the obsolete WEP protocol.
- **Impact:** These actions primarily target **Confidentiality** and **Authenticity** by seeking to bypass standard authentication barriers. A successful port scan maps out an organization's network attack surface, while a successful brute-force or cracking attempt grants the attacker legitimate, authorized access to systems. This can serve as a primary entry point to drop secondary payloads, plant [backdoors](#Backdoors), or harvest internal data.
- **Prevention:** Network perimeters must be hardened by utilizing robust [firewall](01%20Network%20Security.md#Firewall) and [Intrusion Prevention System (IPS)](Intrusion%20Detection%20and%20Prevention.md#Intrusion%20Prevention%20System%20(IPS)) to detect, rate-limit, and automatically block aggressive scanning behavior. To neutralize brute-force attempts, organizations must enforce strong password policies, implement strict account lockout thresholds, and require multi-factor authentication across all external-facing endpoints. Legacy, vulnerable protocols like WEP must be permanently disabled and replaced with modern, secure cryptographic standards (such as WPA3).
- **Recovery:** Following the credential-reset and isolation logic applied to unauthorized access events like [Trojans](#Trojans%20(Trojan%20Horses)), recovery requires immediate verification of system integrity:
    - Initial efforts must focus on immediate [Containment](../06%20Security%20Operations%20and%20Governance/Incident%20Response,%20Forensics,%20and%20Disaster%20Recovery.md#Containment) through **Account Isolation**, revoking access to any compromised accounts, and initiating a global password reset for affected administrative or user profiles.
    - Security teams must run a comprehensive **Root Cause Analysis (RCA)** using firewall and service logs to identify the specific ports or weak protocols that allowed entry, modifying access control lists (ACLs) to block the attacking IP ranges and close unnecessary open ports.
    - Finally, teams should conduct [live forensic](Incident%20Response,%20Forensics,%20and%20Disaster%20Recovery.md#Types%20of%20digital%20forensics) to ensure the intruder did not establish persistent access or alter system configurations during the window of unauthorized exposure.

#### ICMP and RIP-based Attacks

- **Definition:** Network infrastructure exploits that abuse the implicit trust and lack of native authentication in legacy control and routing protocols to manipulate data paths or disrupt service availability.
- **Execution Mechanism:** These exploits combine **Fabrication** and **Modification** techniques at the network and routing layers. In Routing Information Protocol (RIP) attacks, the offender injects completely manufactured or altered RIP routing updates into the network. Because legacy RIP lacks native packet validation, routers blindly accept these updates, allowing the attacker to falsely advertise a malicious device as a trustworthy, optimal next-hop router. Concurrently, the attacker fabricates fraudulent Internet Control Message Protocol (ICMP) error messages—such as _Time Exceeded_ or _Destination Unreachable_—to forcefully terminate active TCP/UDP connections, or transmits malicious _ICMP Redirect_ packets to dynamically alter a client's local routing table on the fly.
- **Impact:** These actions target **Integrity**, **Authenticity**, and **Availability**. Fabricated ICMP error states trigger immediate connection drops, acting as a highly effective tool for a localized **[Denial of Service (DoS)](#DoS%20%28Denial%20of%20Service%29)**. Meanwhile, RIP manipulation and ICMP Redirects forge routing logic to establish an advanced **[Man-in-the-Middle (MitM)](#Man-in-the-Middle%20%28MitM%29)** condition, allowing the attacker to seamlessly intercept, copy (**[Packet Sniffing](#Packet%20Sniffing)**), or manipulate data before it ever reaches its real destination.
- **Prevention:** To secure internal routing, organizations must permanently phase out legacy RIP in favor of modern routing protocols that support explicit cryptographic authentication, such as **OSPFv3** or **BGP** with MD5/SHA signatures. Network firewalls, routers, and host operating systems must be explicitly configured to drop all incoming _ICMP Redirect_ messages (`Type 5`). Furthermore, implementing **Unicast Reverse Path Forwarding (uRPF)** on routers helps validate that incoming packet paths match legitimate routing logic, neutralizing forged control traffic.
- **Recovery:** Similar to the architectural rebuilding and routing-flush logic found in **[DNS Poisoning](#DNS%20Poisoning%20%28DNS%20Cache%20Poisoning%29)** and **[ARP Spoofing](#ARP%20Spoofing)**, recovery requires clearing the manipulated routing states immediately:
    - Initial efforts must focus on immediate [Containment](../06%20Security%20Operations%20and%20Governance/Incident%20Response,%20Forensics,%20and%20Disaster%20Recovery.md#Containment) by isolating the node transmitting the unauthorized protocol traffic and issuing global commands to flush the corrupted routing tables and host caches across all impacted network segments.
    - Security operations must run a **Root Cause Analysis (RCA)** to identify the lack of protocol boundaries that allowed internal routing tables to accept unauthenticated external inputs, updating network Access Control Lists (ACLs) to block rogue routing updates.
    - Because data may have been redirected through a malicious gateway, teams must enforce a global **Session Termination** to invalidate all active bearer tokens and perform an audit to verify that no core configuration data was exfiltrated during the diversion window.
